# 3장. Assembly Language Fundamentals

## 1. Basic Language Elements

Assembly Language를 작성하기 위해 필요한 기본적인 구성 요소와 프로그램의
구조를 알아본다.

### 프로그램의 기본 영역

Assembly 프로그램은 데이터를 저장하는 영역과 실제로 실행할 명령어를
저장하는 영역 등으로 구성된다.

-   **.DATA** : 프로그램에서 사용할 변수와 데이터를 정의하는 영역
-   **.CODE** : CPU가 실행할 명령어가 들어가는 영역
-   **.STACK** : 프로그램 실행 중 사용하는 runtime stack을 저장하는 영역

즉, 데이터를 어디에 정의하고 실행할 명령어를 어디에 작성할 것인지
구분해서 사용한다.

### Windows Service 호출

Assembly 프로그램에서는 Windows에서 제공하는 기능을 함수 형태로 호출할
수 있다.

프로그램 실행이 끝나면 운영체제에 제어권을 돌려주어 프로그램을 종료할 수
있다.

------------------------------------------------------------------------

## 2. Constant Integer Expression

상수 정수 표현식은 **정수 리터럴과 산술 연산자를 이용해서 만든
수식**이다.

예를 들어 정수 값을 이용하여 덧셈, 뺄셈 등의 계산을 표현할 수 있다.

Assembly에서는 이러한 정수 표현식을 이용하여 데이터의 크기나 반복 횟수
등을 지정할 수 있다.

------------------------------------------------------------------------

## 3. Label

**Label**은 Assembly 프로그램에서 명령어나 데이터의 위치를 나타내는
이름이다.

주소를 직접 사용하기보다 이름을 붙여서 사용하면 프로그램을 작성하고
이해하기가 쉬워진다.

### 종류

-   **Data Label** : 데이터가 저장된 위치를 나타낸다.
-   **Code Label** : 실행할 코드의 위치를 나타낸다.

------------------------------------------------------------------------

## 4. Instruction Mnemonic

**Instruction Mnemonic**은 Assembly 명령어를 짧은 단어로 표현한 것이다.

CPU가 수행할 작업을 사람이 알아보기 쉬운 형태의 명령어 이름으로
나타낸다.

Assembly 소스 코드의 명령어는 assembler에 의해 machine language의 byte
형태로 변환된다.

------------------------------------------------------------------------

## 5. Operand

**Operand**는 명령어가 입력이나 출력에 사용하는 값이다.

명령어에 따라 operand의 개수가 달라질 수 있다.

-   Operand가 없는 명령어
-   Operand가 1개인 명령어
-   Operand가 2개인 명령어
-   Operand가 3개인 명령어

2개의 operand를 사용하는 경우에는 일반적으로 다음과 같이 구분한다.

-   **Destination operand** : 결과가 저장되는 대상
-   **Source operand** : 연산에 사용되는 값

따라서 명령어를 볼 때 mnemonic뿐만 아니라 operand가 무엇을 의미하는지도
확인해야 한다.

------------------------------------------------------------------------

## 6. Comment

Comment는 프로그램의 설명을 작성하기 위해 사용한다.

주석은 assembler가 실제 명령어로 처리하지 않기 때문에 프로그램의
동작에는 영향을 주지 않는다.

주석에는 다음과 같은 내용을 작성할 수 있다.

-   프로그램의 목적
-   프로그램을 만든 사람 또는 수정한 사람
-   프로그램을 작성하거나 수정한 날짜
-   프로그램 구현에 대한 설명

### 한 줄 주석

`;`를 사용한다.

세미콜론 뒤의 내용은 같은 줄에서 assembler가 무시한다.

### 여러 줄 주석

`COMMENT` directive와 사용자가 지정한 기호를 이용하여 여러 줄을 한꺼번에
주석 처리할 수 있다.

------------------------------------------------------------------------

## 7. NOP

**NOP**은 아무 작업도 수행하지 않는 명령어이다.

NOP 명령어는 프로그램 저장 공간에서 **1 byte**를 차지한다.

실제로 특별한 작업을 수행하지 않지만, compiler나 assembler에서 코드의
주소를 효율적으로 정렬하기 위한 목적으로 사용되기도 한다.

------------------------------------------------------------------------

# 8. Adding and Subtracting Integers

이 부분에서는 Assembly를 이용하여 정수의 **덧셈과 뺄셈**을 수행하는
프로그램을 작성하고 실행하는 과정을 다룬다.

Visual Studio에서 Assembly 프로젝트를 사용할 때 Irvine 관련 라이브러리와
include 경로를 설정해야 한다.

### Visual Studio 설정

프로젝트 속성에서 다음과 같은 부분을 설정한다.

-   **링커 → 추가 라이브러리 디렉토리**
    -   `C:\Irvine`
-   **구성 속성 → Microsoft Macro Assembler → General**
    -   Include Paths에 `C:\Irvine` 설정

### Irvine32

수업에서는 Irvine32 관련 procedure와 library를 이용하여 Assembly
프로그램을 작성한다.

### 주요 설정

-   **.386** : 프로그램에 필요한 최소 CPU 수준을 지정한다.
-   **flat** : protected mode용 코드를 생성한다.
-   **stdcall** : Microsoft Windows 함수 호출 방식과 관련된 설정이다.

### INVOKE

`INVOKE`는 procedure 또는 function을 호출할 때 사용한다.

즉, 이미 만들어져 있는 procedure를 프로그램에서 실행할 때 사용할 수
있다.

------------------------------------------------------------------------

# 9. Debugging

Assembly 프로그램을 실행할 때 프로그램이 어떤 순서로 실행되는지 확인하기
위해 디버깅을 사용할 수 있다.

### Breakpoint

Breakpoint는 프로그램 실행을 특정 지점에서 잠시 멈추기 위해 설정한다.

프로그램이 breakpoint에 도달하면 실행을 멈추고 현재 레지스터나 변수 등의
상태를 확인할 수 있다.

Visual Studio에서는 다음과 같이 디버깅을 시작할 수 있다.

-   **디버그 → 디버깅 시작**
-   단축키 : **F5**

------------------------------------------------------------------------

# 10. Assembling, Linking, and Running Programs

Assembly 프로그램은 작성한 소스 파일을 바로 실행하는 것이 아니라 여러
단계를 거쳐 실행 파일을 만든다.

### 전체 과정

1.  Assembly 소스 파일을 **assemble**한다.
2.  Object 파일이 만들어진다.
3.  필요한 Object 파일과 library를 **link**한다.
4.  최종적으로 실행 파일인 `.exe` 파일을 만든다.
5.  만들어진 실행 파일을 실행한다.

### 명령어 예시

``` text
ml /c /coff AddTwo.asm
```

Assembly 소스 파일을 object 파일로 변환하는 과정이다.

``` text
link file1.obj file2.obj file3.obj /SUBSYSTEM:CONSOLE /OUT:Program.exe
```

여러 object 파일을 연결하여 `Program.exe`를 만드는 과정이다.

### 생성되는 파일

-   **.lst 파일** : Assembly 코드와 관련된 정보를 확인하는 데 사용한다.
-   **.map 파일** : 프로그램의 메모리 및 주소 관련 정보를 확인하는 데
    사용한다.

------------------------------------------------------------------------

# 11. Defining Data

Assembly에서는 프로그램에서 사용할 데이터를 메모리에 저장할 공간을 직접
정의해야 한다.

**Data definition statement**는 변수에 사용할 메모리 공간을 확보하고
필요한 경우 초기값을 지정한다.

Assembly의 기본 데이터 타입은 데이터의 크기와 signed/unsigned 여부 등에
따라 구분된다.

------------------------------------------------------------------------

## 12. BYTE와 SBYTE

### BYTE

`BYTE`는 **1 byte** 크기의 unsigned 값을 저장하기 위한 데이터 정의
방식이다.

### SBYTE

`SBYTE`는 **1 byte** 크기의 signed 값을 저장한다.

### ? 초기화

`?`를 사용하면 해당 데이터를 처음부터 특정 값으로 초기화하지 않는다.

실행 중에 값을 저장할 목적으로 사용할 수 있다.

### DB

`DB`는 8-bit 데이터를 정의할 때 사용할 수 있다.

------------------------------------------------------------------------

# 13. String

Assembly에서는 문자열을 작은따옴표 또는 큰따옴표로 묶어서 정의할 수
있다.

문자열의 마지막에 값이 `0`인 byte를 넣는 형태를 **null-terminated
string**이라고 한다.

이러한 형태의 문자열은 여러 프로그래밍 언어에서 사용된다.

------------------------------------------------------------------------

# 14. DUP

**DUP** 연산자는 같은 종류의 데이터를 여러 개 저장하기 위해 사용한다.

반복할 데이터의 개수를 정수 표현식으로 지정한다.

예를 들어 여러 개의 같은 크기 데이터를 한꺼번에 확보해야 할 때 사용할 수
있다.

------------------------------------------------------------------------

# 15. WORD와 SWORD

### WORD

`WORD`는 **16-bit 정수**를 저장할 공간을 만든다.

### SWORD

`SWORD`는 signed 형태의 **16-bit 정수**를 저장할 공간을 만든다.

------------------------------------------------------------------------

# 16. DWORD와 SDWORD

### DWORD

`DWORD`는 **32-bit 정수**를 저장하기 위한 데이터 정의 방식이다.

### SDWORD

`SDWORD`는 signed 형태의 **32-bit 정수**를 저장한다.

따라서 WORD 계열보다 더 큰 크기의 정수를 저장할 수 있다.

------------------------------------------------------------------------

# 17. BCD

Intel에서는 packed **Binary Coded Decimal(BCD)** 정수를 10-byte 형태로
저장할 수 있다.

각 byte에는 일반적으로 두 개의 10진 숫자가 저장되며, 가장 높은 byte는
다른 부분과 처리 방식이 다르다.

------------------------------------------------------------------------

# 18. REAL 데이터 타입

실수를 저장하기 위한 데이터 타입도 제공된다.

-   **REAL4** : 4 byte single-precision floating-point
-   **REAL8** : 8 byte double-precision floating-point
-   **REAL10** : 10 byte extended-precision floating-point

즉, 저장하는 크기에 따라 사용할 수 있는 REAL 타입이 달라진다.

------------------------------------------------------------------------

# 19. Little-Endian

x86 프로세서는 메모리에 데이터를 저장하고 가져올 때 **little-endian**
방식을 사용한다.

Little-endian에서는 하나의 값이 여러 byte로 구성되어 있을 때 **낮은
byte부터 낮은 메모리 주소에 저장**된다.

Assembly에서 메모리 값을 확인할 때 중요한 개념이므로 데이터가 메모리에
어떤 순서로 저장되는지 확인해야 한다.

------------------------------------------------------------------------

# 20. .DATA? Directive

`.DATA?`는 **초기화되지 않은 데이터**를 선언할 때 사용한다.

특히 큰 크기의 초기화되지 않은 데이터를 정의할 때 사용할 수 있다.

이 방법을 사용하면 프로그램에 실제 초기값을 저장할 필요가 없기 때문에
컴파일된 프로그램의 크기를 줄이는 데 도움이 된다.

------------------------------------------------------------------------

# 21. Code와 Data 영역 전환

Assembly에서는 프로그램을 작성하면서 필요에 따라 code 영역과 data 영역을
전환할 수 있다.

예를 들어 특정 코드에서만 사용하는 데이터를 별도의 위치에 정의할 수도
있다.

따라서 프로그램 전체에서 사용하는 데이터뿐만 아니라 특정 부분에서
사용하는 데이터를 구분하여 작성할 수 있다.

------------------------------------------------------------------------

# 22. Symbolic Constants

Assembly에서는 숫자나 문자열을 직접 반복해서 사용하는 대신 **symbolic
name**을 만들어 사용할 수 있다.

이렇게 하면 코드에서 의미를 알기 쉬운 이름을 사용할 수 있다.

------------------------------------------------------------------------

## Equal-sign Directive

`=` 지시어는 기호 이름을 정수 표현식과 연결한다.

프로그램에서 특정 숫자 값을 이름으로 표현할 때 사용할 수 있다.

------------------------------------------------------------------------

## EQU

`EQU`는 symbolic name을 정수 표현식 또는 임의의 텍스트와 연결한다.

즉, 프로그램에서 반복해서 사용할 값을 하나의 이름으로 정의할 수 있다.

------------------------------------------------------------------------

## TEXTEQU

`TEXTEQU`는 `EQU`와 비슷하지만 **text macro**를 만든다.

반복해서 사용할 텍스트를 하나의 이름으로 정의할 때 사용할 수 있다.
